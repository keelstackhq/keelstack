# D-031: Every repo describes its systems and credentials in system.toml

- Date: 2026-11-27
- Scope: all
- Status: accepted
- Supersedes: —

## Context

Repos use external systems (hosting, registries, DNS, LLM APIs) and hold credentials for them.
Nothing records why a secret exists, who owns it, what it can do, where it is stored and used,
when it expires or how to rotate it, so secrets grow unknown and stale. Agents also need to
know which alternatives exist for a capability without holding any key.

## Decision

- Every repo carries `system.toml` at its root: cleartext TOML, names and metadata only, never
  values; `version = 1`; unknown keys are an error (exit 3).
- It describes external systems (`[[provider]]`: capability, account, CLIs, alternatives), every
  credential (`[[credential]]`: purpose, owner, scopes, where used = storage plus consumers,
  created and expiry dates, `max_ttl`, rotation strategy, command and steps) and keyless trusts
  (`[[trust]]`).
- hoist owns it: `hoist system init|check|explain|stamp`, JSON Schema `hoist/schema/system.schema.json`,
  spec §17 in `hoist/docs/superpowers/specs/2026-10-16-hoist-design.md`. `hoist system init` drafts
  the file only if absent; `hoist system check` (offline) fails on undeclared or unused secrets,
  expired or expiring credentials, missing metadata, `max_ttl` violations and long-lived
  credentials where a keyless option exists.
- `SYSTEM.md` is generated by `hoist system explain --write` (`--check` in CI); never hand-edit it.
- `hoist system check --live` asks each provider, GET only (and read-only `fly … list`), with tokens
  from the environment; a missing token is `unknown`, never a failure. A weekly `system-check`
  workflow runs it and keeps one issue current.
- `hoist secrets rotate <credential-id>` follows the credential's `rotation.strategy`: `auto`
  (Cloudflare, Fly) mints the new credential, verifies it, writes every storage, stamps
  `system.toml` and revokes the old one last; `assisted` and `manual` print the steps (exit 2).
  `hoist system stamp <id> --created DAY --expires DAY [--ref ID]` records a rotation.
- Agents never hold keys and hoist never prints values.
- Describing a provider in `system.toml` does not make it a hoist-managed service; the closed list
  of D-029 stays.
- An org catalog of alternatives per capability is data (spec §17.6), shipped in the decisions
  channel (`decisions/channel/pieces/catalog/files/catalog.toml`); `hoist system explain` lists the
  alternatives of each provider's capability.

## Consequences

- Spec §17 is the contract; hoist and its skill document the commands.
- A repo that adds a secret adds its `[[credential]]` in the same PR, or `hoist system check` fails.
- No existing decision changes.
